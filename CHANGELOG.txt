Quick Menu Hotkeys - Changelog

== v1.10.6 (2026-07-08) ==
- New: hotkeys now work immediately after loading a save — including keys the game has no native binding for (e.g. O for Options). Previously those only worked after another menu had been opened once per session.
- Update-proof: the internal PanelManager pointer path is now derived statically from the game binary at startup (located via the FindPanelTop call-site anchor) instead of being hardcoded. It is read fresh from the game files every launch, so a future update that shifts the offsets is picked up automatically with no mod update needed. If the anchor ever fails to match, the mod falls back to learning the path from the first live menu open.
- New: second, independent fallback for the mode/sub-mode offsets — if the ModeSwitcher scan ever fails after an update, they are derived from the dynamically scanned menu-state flag offsets instead (relation verified on 1.12 and 1.13).
- Hardened: chain-resolved PanelManager values are plausibility-checked and live-validated before use, so a wrong path can never hand the game a garbage pointer silently.

== v1.10.5 (2026-07-08) ==
- Updated for game version 1.13.01 (2026-07-08). Fixes all hotkeys being dead: the July update moved the mainChar mode/sub-mode block by -8 bytes, so the safety gate read the wrong byte (always 0x00) and blocked every key press as "unsafe state".
- New: the mode/sub-mode/panel-state offsets are now re-derived at startup from the game's ModeSwitcher function (via the "ingame-global" string xref) instead of being hardcoded — survives future struct shifts. On scan failure the old defaults stay in place.
- Hardened: the safety gate now also checks the top-level mode byte (must be 4 = ingame), so loading screens with a stale gameplay sub-mode no longer slip through.
- New: PanelManager chain auto-relearn — 1.13 removed the static load idiom the proactive scanner matched (callers now use per-object virtual getters). The chain is now learned from the live pointer at panel captures instead: a candidate is only promoted after agreeing with the live pointer on 3 separate captures, and is demoted again on any divergence or panel-call crash. Restores the stale-pointer protection without ever trusting a coincidental match.

== v1.10.4 (2026-05-16) ==
- Updated for game version 1.07.00 (2026-05-16). Fixes the instant crash that occurred when the Pet hotkey was pressed: the post-open sub-tab switch used two hardcoded helper addresses (FindPanelTop, SetSubTab) that were valid for the 1.06.00 build but pointed at unrelated code in 1.07.00, taking down the game on the very first call.
- New: helper addresses are now resolved dynamically by scanning OpenPanel's body. FindPanelTop is identified as the first CALL following the LEA RDX = "MainMenuView2" string load; SetSubTab is identified by its unique argument-setup signature (XOR R9D/R8D + MOV EDX,[reg+0x1AC] + CALL). Survives future address shuffles.
- Hardened: if either helper cannot be located, the sub-tab post-switch is silently skipped instead of crashing — the panel still opens at the game-default sub-tab.

== v1.10.3 (2026-05-11) ==
- Updated for game version 1.06.00 (2026-05-11). All panel hotkeys, toggle-close, and proactive PanelManager resolution work again after the update shifted internal addresses (OpenPanel, FindPanel, panel-state offsets).
- Fixed: Instruction-length decoder now recognizes the 2-byte alignment NOP (66 90) so hooks no longer abort when a function prolog starts with operand-size-prefixed padding.
- Improved: OpenPanel/FindPanel disambiguation — when the cross-reference scan finds both candidates with the same match score, the heuristic now checks which one calls the other (OpenPanel calls FindPanel internally) and swaps roles if needed. Prevents the hook from being installed on the wrong function after future shuffles.
- New: BlockOverlappingInputs (default ON) — when a controller modifier (ControllerModifier / PSModifier) is held, the bound panel buttons are masked out of the data the game sees. Prevents the same press from triggering both the panel hotkey and the default in-game action (e.g. L1 + D-Pad Right opening a menu while also consuming an item). The modifier button itself is preserved so its game function (e.g. LB = block) keeps working. XInput path covers Xbox + Steam-Input-translated controllers; native HID path covers DualSense / DualShock 4 directly.
- Hardened: bound buttons are now delayed by one polling tick (~16 ms) so the modifier has time to register before edge-triggered game actions fire (horse whistle on D-Pad Up, etc.). Catches both the press-edge race (panel button hits a frame before modifier) and the release-glitch (modifier lifted a frame before panel button). Single taps on bound buttons still reach the game, just one tick later — imperceptible.
- Improved: XInput init now reuses an XInput DLL the game already loaded rather than always loading xinput1_4.dll, so input-block hooks always sit on the same module the game's calls go through.

== v1.10.2 (2026-04-23) ==
- Updated for game version 1.0.4.1 (2026-04-23) — struct layout, sub-mode values, and PanelManager load pattern changed; scanners re-adapted. All panel hotkeys, toggle-close, and proactive PanelManager resolution work as before.
- Improved: Menu-state pointer and PanelManager chain are now resolved dynamically via byte-pattern anchors instead of a fixed CALL-target heuristic — survives future updates that shift register usage or offsets.
- Improved: Hook installer detects and follows `FF 25` / `E9` redirect thunks on the hook target, preventing trampoline corruption if a future update inserts a thunk at the OpenPanel address.

== v1.10.1 (2026-04-15) ==
- Added: D-Pad support for PS controllers in Native HID mode (DPadUp, DPadDown, DPadLeft, DPadRight as PSButton values)

== v1.10 (2026-04-08) ==
- New: Native PS5/PS4 controller support via HID Raw Input (DualSense, DualSense Edge, DualShock 4)
- Fixed: Pressing a hotkey after the game closed a panel (e.g. using an item) no longer requires a double press. The mod now verifies the panel's state flag at key-press time before deciding to toggle-close.


== v1.9.3 (2026-04-04) ==
- Fixed: Toggle state no longer desyncs when the game closes a panel (e.g. using an item, teleporting from map). Previously required pressing the hotkey twice after a game-initiated close.
- Added: Log output now includes timestamps ([HH:MM:SS.mmm]) for easier debugging

== v1.9.2 (2026-04-04) ==
- Fixed: Switching from a modifier-bound panel to the plain key on the same base key (e.g. Shift+J → J) no longer closes the menu. The debounce delay is now skipped when the intent is unambiguous.

== v1.9.1 (2026-04-02) ==
- Added: Debug log now includes CRC32 hash of meta/0.papgt to help detect modded game files (JSON mods etc.) when troubleshooting
- Fixed: Window detection now uses the exact game window class name instead of blind enumeration, preventing conflicts with overlays (Discord, Steam, etc.)
- Added: Game window class/title logged on startup for easier troubleshooting

== v1.9 (2026-03-30) ==
- Fixed: Key blocking (OverrideGameKeys) no longer activates during mod initialization. Previously, if window subclassing failed, I/J/K/M would be blocked with no replacement hotkeys active.
- Fixed: Toggle-close (pressing same hotkey to close panel) now runs on the game thread via PostMessage, preventing potential cross-thread memory corruption.
- Fixed: PanelManager pointer is now refreshed from the global chain before every panel open, preventing stale pointer crashes after scene changes or loading screens.
- Improved: RIP-relative instruction check in hook installer now covers all x64 opcodes (previously only checked MOV/LEA/CMP). Prevents unsafe trampoline relocation if a game update changes the function prologue.
- Improved: Trampoline memory is locked to execute-read after setup (was execute-read-write).
- Improved: OpenPanel now passes nullptr as data parameter, letting the game resolve the default tab per panel (previously used a static pointer captured from InventoryEquipmentPanel).
- Improved: Log now warns when controller is enabled with a modifier but no ControllerButton is assigned to any panel.
- Improved: Log now warns that a controller modifier button with a game function (e.g. LB=block) will trigger both actions simultaneously.

== v1.8.1 (2026-03-29) ==
- Compatibility: Hotkeys without a modifier are now blocked when Shift, Ctrl, or Alt is held. Prevents conflicts with other mods that use modifier+key combos on the same key (e.g. Private Storage Anywhere using Shift+I while Inventory uses plain I).

== v1.8 (2026-03-29) ==
- New: Safety check — hotkeys are blocked during cutscenes, QTEs, and minigames to prevent UI corruption
- Update-proof: Menu state flag offsets (for toggle-close) are now scanned dynamically instead of hardcoded. Survives game patches that shift struct layouts.
- Fixed: Updated menu state flag offset changed by game patch 1.01.00 (0xcc4 → 0xcc5)

== v1.7.1 (2026-03-28) ==
- Fixed: OverrideGameKeys no longer blocks internal game UI calls (settlement interface, NPC menus, etc.). Now only blocks when the user is physically pressing the game's default key (I/J/K/M).

== v1.7 (2026-03-28) ==
- New: Per-panel keyboard modifiers — use Shift+J, Ctrl+J etc. to bind multiple panels to the same key with different modifiers
- New: INI hot-reload — press a configurable key (default F11) to reload all settings without restarting the game
- Improved: OverrideGameKeys now fully blocks game-triggered I/J/K/M panel opens, preventing conflicts with modifier combos
- Improved: Modifier key debounce — plain keys are delayed briefly when modifier bindings exist, preventing accidental triggers
- Crash protection: stolen bytes are validated for RIP-relative instructions before hooking. If the trampoline crashes after a game update, the mod disables itself instead of crashing the game.
- Fixed: XInput initialization logging was called before log file was opened
- Cleaned up INI file with better comments and documentation

- Expanded INI key reference: F13-F24, navigation keys, modifier keys (LShift/RShift etc.), punctuation, mouse side buttons, media keys
